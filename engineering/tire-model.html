The problem

The tires are the only part of the car that touches the ground, so every suspension and setup decision depends on how they generate force. The TTC tests tires on a machine at Calspan and records hundreds of thousands of samples per round, sweeping slip angle, load, camber, and pressure. That raw data is too noisy and too large to design around directly.

This tool condenses it into a small set of Magic Formula coefficients: a compact equation that predicts lateral force and aligning moment for any load and camber inside the tested range.

How it works

  1. Load a test round. Reads raw Calspan TTC files and identifies the tire (compound, diameter, width) from the file's own metadata.
  2. Segment the data. Auto-detects every tested normal load and camber angle, then splits the round into one slice per test condition.
  3. Smooth each sweep. Fits a smoothing spline through the noisy slip-angle sweep so the model is fit to the tire's real trend, not sensor noise.
  4. Fit the Magic Formula. Solves for the coefficients with nonlinear least squares in stages: base curve first, then load sensitivity, then camber sensitivity.
  5. Review and export. Plots raw data, smoothed curves, and the fitted model together, and exports the coefficients for the team to use.

The model

The Pacejka Magic Formula is an empirical tire model: rather than simulating rubber physics, it uses one flexible curve shape that matches measured tire behavior very closely. The tool follows the MF-Tire 6.1 formulation. Every force and moment is built from the same general form:

$$\begin{gathered}y = D\sin\!\Big[C\arctan\!\big\{Bx - E\,(Bx - \arctan Bx)\big\}\Big] + S_V \\[6pt] x = X + S_H\end{gathered}$$
\(D\)
Peak value: the most force the tire can make.
\(C\)
Shape factor: controls how the curve rises and falls off after the peak.
\(B\)
Stiffness factor. \(BCD\) is the slope at zero slip, the tire's cornering stiffness.
\(E\)
Curvature factor: how sharp or rounded the curve is around the peak.
\(S_H,\ S_V\)
Horizontal and vertical shifts from ply steer, conicity, and camber.

Lateral force, \(F_{y0}\)

Each factor is itself a function of normal load and camber, which is what lets one set of coefficients cover every tested condition. Load enters as the normalized change from a reference load \(F_{z0}'\), and camber as \(\gamma^* = \sin\gamma\):

$$\begin{gathered}df_z = \frac{F_z - F_{z0}'}{F_{z0}'} \\[6pt] \mu_y = (p_{Dy1} + p_{Dy2}\,df_z)(1 - p_{Dy3}\,\gamma^{*2}) \\[6pt] D_y = \mu_y F_z\end{gathered}$$
$$\begin{gathered}K_{y\alpha} = p_{Ky1}F_{z0}'\,\sin\!\left[p_{Ky4}\arctan\!\left(\frac{F_z}{(p_{Ky2} + p_{Ky5}\gamma^{*2})\,F_{z0}'}\right)\right](1 - p_{Ky3}\,|\gamma^*|) \\[6pt] B_y = \frac{K_{y\alpha}}{C_y D_y}\end{gathered}$$
$$\begin{gathered}E_y = (p_{Ey1} + p_{Ey2}\,df_z)\big[1 + p_{Ey5}\gamma^{*2} - (p_{Ey3} + p_{Ey4}\gamma^*)\,\mathrm{sgn}(\alpha)\big] \\[6pt] \alpha_y = \alpha + S_{Hy}\end{gathered}$$

Here \(\mu_y\) is the friction coefficient, which drops as load rises (load sensitivity), and \(K_{y\alpha}\) is the cornering stiffness.

Aligning moment, \(M_{z0}\)

The self-aligning moment is the lateral force times the pneumatic trail \(t\) (how far behind the contact patch center the force acts), plus a residual moment \(M_{zr}\):

$$M_{z0} = -\,t\,F_{y0} + M_{zr}$$
$$\begin{gathered}t = D_t\cos\!\Big[C_t\arctan\!\big\{B_t\alpha_t - E_t(B_t\alpha_t - \arctan B_t\alpha_t)\big\}\Big]\cos\alpha \\[6pt] M_{zr} = D_r\cos\!\big[\arctan(B_r\,\alpha_r)\big]\cos\alpha\end{gathered}$$

The Python rebuild

The original tool is 11 MATLAB scripts. I'm porting it to Python with a Streamlit app, so future vehicle dynamics members without a MATLAB license or a scripting background can run a tire fit by double-clicking a launcher, loading a round, and pressing Run Fit.

  • Fits every tested load and camber automatically. The MATLAB version was hardcoded to one condition (50 lbf, 0° camber), so its load and camber terms were never truly fit.
  • Fixes bugs found during the port, including a missing lbf-to-newton conversion in the load-sensitivity stage and the wrong slip angle in the aligning-moment residual term.
  • Tested as it's ported. Each function is checked against the original MATLAB output, or hand-calculated values where MATLAB isn't available, before it's considered done.
  • Built for a lap sim. The model equations are kept as standalone functions, ready for a future lap-simulation integration.

Next steps

  • Correlate with real team data. The model is fit to machine test data. Its predictions need to be checked against Crimson Racing's own on-car data logs and skidpad runs, then adjusted with scaling factors so the curves match the car on our track surface.
  • Estimate 16″ longitudinal data. The TTC brake and drive tests we have only cover the 18″ tires, while the team runs 16″. Longitudinal (braking and acceleration) behavior for the 16″ tire has to be estimated from the 18″ data and the 16″ cornering results.
  • Port the longitudinal and overturning models. Bring the MATLAB \(F_x\) and \(M_x\) fitting into the Python tool, then combine lateral and longitudinal for combined slip (cornering while braking or accelerating).
  • Load and camber cross terms. Fit how camber sensitivity changes with load, which needs test data at combined nonzero camber and off-nominal load.
  • Lap sim integration. Feed the fitted model into a lap-time simulation.
